# 新版商业模板与内容计划

用户已认可蓝白排期、黑红看板、红金框架三个方向。`assets/design-catalog.json`列出30套实际文件，每套6页；主分析页为30种不同图形结构，另有总体表现、行动与复盘等共用组件。颜色变化不增加模板数。

## 使用方式

1. 在图库按用途查看六页真实渲染，选最贴近内容的模板。可以只用其中几页，或组合合适的内容页。
2. 先完成需求澄清，再从`assets/template-plans/T01.json`等复制到任务目录，补真实`design.requirements`、方案记录及`narrative`主线；每页补`purpose/message/layout_reason`和发现/证据/行动引用，替换标题与原始资料。定量图表和指标须先按 @references/data-analysis.md 分析并绑定，不能沿用合成数字；按 @references/report-logic.md 输出提纲和已绑定计划后，再运行`generate.py`。库中计划是素材源，不是已澄清的业务任务；保留原计划和源模板。按实际内容跨模板选页或重组，禁止循环套用其中三四页拼稿。
3. `office_`版式读取页面`data`字段，所有示例数字都在计划中显式提供，生成器不自动补示例事实。`items`含`title/body`；`steps`是阶段名；`metrics`含`title/value`；`headers/rows`是表格；`chart`含`categories/series`。保留所用版式需要的结构字段，不能只换总标题而留下合成数字。
4. 甘特额外字段`schedule`逐行给`name/start/end/progress`：月份1至12、进度0至1，按计划跨度准确绘制；`milestones/progress/progress_label`必须与真实资料一致。季度或周粒度需调整结构，不能把月份标签硬换后仍声称时间准确。
5. 组合图表第一序列为数量，第二序列为比例（0.124代表12.4%），`secondary_max`是右轴上限；数据表和嵌入工作簿保持原生。费用分解示例为逐项正负金额柱，不是累计瀑布，不能误读成现金流累计结果。

   数量轴包含负数时会保留负值范围；比例轴上限小于实际数据会明确拒绝，不能裁掉曲线。单页`items`超过6条会拒绝，先拆页再生成；六项以内也应按所选结构（如四象限、三项概览）选择实际展示的字段，不能只追加数据却不调整逐页计划。
6. 分层框架用`tier_titles/tier_labels`；路线图用`periods/roadmap_cells`；泳道用`lane_tasks`；进度组合用`project_status`。对应字段例子均在该套JSON中，不猜测缺失的业务含义。
7. 示例计划带`demo:true`，每页带`synthetic:true`并显示“合成模板”。真实业务稿须逐项替换数据、补来源、移除相应示例标记，再记录当前任务的真实视觉选择；库的方向认可不替代新任务的内容和授权。

## 配色与可编辑性

十套配色来自用户商业参考的色彩关系，由人工取近似色并调整文字对比；不是声称从原PPT精确提取色值。前4套为蓝白系，2套黑红系，4套红金／红白系；正式稿优先公司品牌规范。

分层椭圆、台座、渐变、箭头、表格和组合图表均由原生对象构成。三张生图仅用于方向参考，不作整页PPT背景；复杂参考插画若另用图片，应单独说明内部不可编辑。网页商业案例、用户售卖截图不进入分发包；本包保留自己生成的预览、原创结构与有许可的素材。
